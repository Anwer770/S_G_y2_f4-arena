## 3) العقود المقاسة

### التخزين واللغة الطبيعية

- جميع قارئات القوائم الست عشرة تمر بعقد `loadArray`: الغياب والتلف والشكل غير المصفوفي يعيد fallback، بينما `[]` قيمة مستخدم صالحة ولا تتحول إلى بذور.
- معرّف مساحة العمل القديم غير المنصّص يهاجر إلى JSON منصّص؛ `null` والقيمة الفارغة يعودان إلى `ws_main`.
- تُطبّع مصفوفات المهمة (`subtasks` و`checklist` و`comments` و`tags` و`dependencies`) كي لا تكسر بيانات قديمة الواجهة.
- محلل الإضافة السريعة يختبر بدائل أيام الأسبوع والساعة والأولوية والتصنيف، بما فيها اليوم نفسه لكل يوم من الأحد إلى الخميس كي يُختبر قرار «الأسبوع القادم».

### التصدير والاستيراد

- JSON وCSV وXLSX تعمل بالبيانات المحفوظة وبالوسيط الصريح؛ CSV يربط المشروع وعضو الفريق ويحمي الصيغ.
- استيراد المهام يغطي عناوين الأعمدة العربية والإنجليزية، الحالات والأولويات الأربع، قص التقدم إلى `0..100`، الوسوم العربية/الإنجليزية، الصف الفارغ، صف العنوان المفقود، فشل قارئ الملف وحارس الحجم عند رمي `Error` أو نص أو قيمة فارغة.
- الاستيراد الموحّد ينشئ الطلبية والمهمة والالتزام في عملية الربط الثلاثي، ويغطي كل بدائل العميل والمبلغ وتاريخ التسليم والمندوب، والقيم الافتراضية، وفشل القراءة.
- اختبار عطب التخزين يتعمد إرجاع `tasks/projects/team` ناقصة ليثبت أن بدائل المستورد (`[]` و`p_core` و`m1`) لا تتسبب في رمي أو حفظ زائف.

### الأتمتة

- إنشاء الطلبية يقيس التسلسل فوق أعلى رقم قائم، الروابط الاختيارية، البدائل عند حقل خالٍ، ومطابقة معرف/اسم عضو الفريق.
- المحرك يقيس التقدم فقط، التسليم بـ100% أو بالحالة أو بإتمام المهام الفرعية، التأخير، الاستحقاق المالي، الملغى، الالتزام الموفى، الالتزام بلا تاريخ، وعدم الكتابة عندما لا يتغير شيء.
