# 27 — المكوّنات المالية الحرجة (R60)

> **التاريخ:** 2026-11-07
> **النطاق المقصود:** `FinancialModule` و`FinancialModal` و`CentralUnifiedLedger` فقط.

## الهدف

تُدخِل هذه الدفعة أول شبكة اختبارات مكوّنات مستقلة عن مقام H16 للوحدات. لا تُحوَّل
اختبارات المنطق الحالية إلى jsdom ولا تتغير عتبات تغطيتها؛ بدلاً من ذلك تشغّل شبكة DOM
صغيرة السلوكيات التي يتوقف عليها تسجيل المال وعرضه.

## البنية المضافة

| العنصر         | القرار                                                                                         |
| -------------- | ---------------------------------------------------------------------------------------------- |
| بيئة المكوّنات | `vitest.components.config.ts` يستخدم `jsdom` ولا يبحث إلا في `tests/components/**/*.test.tsx`  |
| التنظيف        | `tests/components/setup.ts` يستدعي `cleanup()` بعد كل حالة                                     |
| مكتبة التفاعل  | `@testing-library/react` و`@testing-library/user-event` كاعتماديات تطوير                       |
| أمر التشغيل    | `npm run test:components`، ويشغله CI و`npm run verify` قبل تغطية الوحدات                       |
| حماية H16      | يبقى `vitest.config.ts` على `environment: 'node'` و`tests/unit/**/*.test.ts` ومقام تغطيته نفسه |

يُشغّل `npm run test:unit` شبكة الوحدات القائمة وحدها كما كان، بينما شبكة R60 صريحة
ومستقلة؛ لذا لا تُخلط أرقام تغطية DOM الجديدة بالبوابة المحاسبية/التخزينية المحروسة.

## عقد السلوك المحروس

الملف [`tests/components/financial-critical.test.tsx`](../../tests/components/financial-critical.test.tsx)
يحتوي أربع حالات قصيرة، ثلاث منها معايير قبول الدفعة مباشرة:

1. **إضافة قيد:** يفتح المستخدم `FinancialModule`، يملأ رقم السند ومبلغاً ووصفاً، ثم يحفظ؛
   يعيد الحاوي القيد إلى المكوّن ويظهر في صف جدول اليومية بالمبلغ والحساب والوصف.
2. **تطابق الأرقام المعروضة:** ثلاث حركات بقيم 1,200 و300 و200 ريال تجعل تذييل اليومية
   يعرض 1,700.00 YER، ومؤشرات الفترة تعرض وارد 1,500 ومصروف 200 وصافي 1,300.
3. **رفض الحساب الفارغ:** يملأ المستخدم الرقم والمبلغ بلا حساب ثم ينفذ الحفظ النهائي؛
   تظهر رسالة `يرجى اختيار أو تحديد اسم الحساب.` ولا يُستدعى `onSave`.
4. **الدفتر المركزي:** ينفذ المستخدم «تسوية» لالتزام معلق؛ يعيد الحاوي القائمة المحدّثة
   فيتحول الزر والحالة إلى «✓ مسدد» و«تم الوفاء». تحفظ هذه الحالة عقد التحديث المرئي
   لـ`CentralUnifiedLedger` من دون ربط الاختبار بتخزين المتصفح أو تصدير Excel.

## تحسين قابلية الوصول المصاحب

أُضيفت روابط `label`/`id` لحقول رقم السند واسم الحساب ومبلغ YER في `FinancialModal`.
هذا ليس تغييراً في قواعد الإدخال؛ بل يجعل الحقول الحرجة قابلة للوصول بلوحة المفاتيح
وقابلة للاستهداف الدلالي في الاختبار بدلاً من الاعتماد على ترتيب عناصر النموذج.
