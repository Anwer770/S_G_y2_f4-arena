## 2. العقود المحروسة

`tests/unit/alertsEngine.test.ts` يحرس خمسة عقود مترابطة:

1. رصيد المنتج يحسب الإذن الوارد الموجب فقط، ويستثني الحالة العربية الدقيقة `ملغي`
   وكذلك الكميات الصفرية والسالبة وغير المنتهية؛ التنبيه الناقص يحفظ ترتيب الأولوية
   ويعرض الوحدة إن وُجدت أو صياغة آمنة إن غابت.
2. التاريخ المكتوب بصيغة `YYYY-MM-DD` يتحقق كتاريخ تقويمي UTC كامل، لا كتاريخ
   JavaScript قابل لتطبيع يوم مستحيل؛ الشهر واليوم المستحيلان لا يصنعان استحقاقاً.
3. الالتزام القديم الذي يستخدم `due` و`تم الانجاز`، والالتزام الحديث الذي يستخدم
   `endDate` و`status`، يمران عبر محرك واحد ولا يظهر المنجز أو الملغي كدين مستحق.
4. مبلغ الالتزام غير الموجب أو غير المنتهي، أو الدفعة غير المنتهية، والتاريخ الغائب
   أو غير الصحيح، لا يصنعون تنبيهاً زائفاً؛ تستمر المبالغ والعملات الصحيحة بالظهور
   في التفاصيل.
5. الملخص النهائي يعدّ النوعين فقط (`stock` و`debt`) ويبقى متسقاً مع قائمة التنبيهات.

## 3. العيوب التي كشفها العقد وإصلاحها

كشف الاختبار الأحمر أربعة عيوب تشغيلية حقيقية:

- كان الاعتماد على `Date.parse` يقبل تاريخاً مثل `2026-02-31` بعد أن يطبّعه إلى يوم
  آخر. أضيف محلل تقويمي صارم يطابق النص ومكوّنات UTC معاً.
- كان حساب المخزون يضم أذون `ملغي` والكميات السالبة أو غير المنتهية، فيرفع الرصيد
  المصطنع ويخفي النقص. صار يضم الإذن الوارد الموجب السليم فقط.
- كان نوع الإدخال محصوراً عملياً في `DebtCommitment`، بينما `App.tsx` يمرر
  `Commitment[]` القديم إلى `computeSystemAlerts`. صار المحرك يدعم النموذجين مع
  تضييق صريح لتاريخ الاستحقاق وحالة الإغلاق.
- كانت قيمة مبلغ أو دفعة غير منتهية تمر عبر التحويل العددي، فتولّد تنبيهاً بقيمة
  `∞` أو تخفي تنبيهاً سليماً. صار مبلغ الالتزام غير المنتهي يُرفض، والدفعة غير
  المنتهية تُهمل من مجموع المسدد.

هذه إصلاحات للمصدر، لا ترخيص لاختبارات شكلية أو تخفيض للقياس.
