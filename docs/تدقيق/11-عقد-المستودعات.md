# 11 — عقد المستودعات: لا مجموعة خارج الطبقة المعلَنة (R45 · 3.34.0)

> السؤال الذي تحسمه هذه الدفعة: **كم مستودعاً يعرف كيف يقرأ ويكتب بنفسه؟**
> الجواب قبل R45: أربعة ملفات، ثمانية استدعاءات مباشرة للمحوّل، وأربع صيغ مختلفة لسؤال «ماذا نفعل حين لا توجد بيانات؟».

---

## 1) الحالة قبل

| الملف | الاستدعاءات المباشرة لـ`indexedDBStorage` | المجموعة |
|---|---|---|
| `DebtRepository.ts` | 2 | التزامات الديون `suite_debts_commitments_v1` |
| `CustomerRepository.ts` | 4 | زيارات العملاء `suite_customers_visits_v2` · زيارات الأطباء `suite_doctors_visits_v1` |
| `FinancialRepository.ts` | 3 | القوائم المنسدلة `suite_fin_{type}_v2` |
| `WorkTaskRepository.ts` | استيراد **ميت** (0 استخدام) | — |

كل واحدة كانت تصوغ القاعدة بنفسها:

```ts
const data = indexedDBStorage.getItemSync<T[]>(key);
return Array.isArray(data) ? data : DEFAULTS;          // ثلاث نسخ متطابقة
```

والقوائم المالية كانت الوحيدة التي **تزرع**:

```ts
if (!data || !Array.isArray(data)) { indexedDBStorage.setItemSync(key, defaults); return [...defaults]; }
```

النتيجة: سلوكان مختلفان لسؤال واحد، ومحوّل تخزين مسمَّر في أربعة مستودعات — أي أن استبدال المحرّك (SQLite/سحابة) كان يعني تعديل كل ملف بدل تعديل نقطة الحقن الواحدة.

## 2) الحالة بعد

المجموعات الثانوية الأربع انتقلت إلى **العقد نفسه** `createCollectionRepository`:

| المجموعة | `fallback` | `seed` |
|---|---|---|
| التزامات الديون | `DEFAULT_DEBT_COMMITMENTS` | `false` (القراءة لا تكتب) |
| زيارات العملاء | `DEFAULT_CUSTOMER_VISITS` | `false` |
| زيارات الأطباء | `DEFAULT_DOCTOR_VISITS` | `false` |
| القوائم المالية | `defaults` من المستدعي | **`true`** — السلوك القديم محفوظ بنصّه |

أُضيف خيار `seed?: boolean` إلى `CollectionOptions` لأن الزرع كان **سلوكاً قائماً** في القوائم المالية، وليس عيباً يُصلح: تحويله إلى «لا كتابة» كان سيغيّر ما يُخزَّن بعد أول فتح للشاشة. الافتراضي `false` يحفظ قاعدة الطبقة الجديدة: **القراءة لا تكتب**.

الاستثناء الوحيد الباقي لاستيراد المحوّل هو `BaseRepository.ts` — لأنه **نقطة الحقن** (`constructor(key, defaults, storage)`).

## 3) الحرّاس

**G34 — نصّي:** لا ملف تحت `src/database/repositories/` (عدا `BaseRepository.ts`) يستورد `indexedDBStorage`؛ ويُتحقّق في الوقت نفسه أن نقطة الحقن ما زالت موجودة (كي لا تُحذف وتصبح البوابة خضراء بلا معنى).

**G35 — سلوكي (15 حالة):** يستدعي **الواجهة العامة** للمستودعات الحقيقية داخل DOM وهمي:

| المحور | الحالات |
|---|---|
| الغياب | 3 مجموعات ⇒ الافتراضي **بلا كتابة** في المفتاح |
| الفراغ | `[]` ⇒ `[]` صالحة (لا تُعتبر غياباً) |
| التلف | `{ليس JSON` · `null` ⇒ الافتراضي، والخام **لم يُمسح** |
| الكتابة | تُكتب وتُقرأ بنفس الشكل |
| الزرع | القوائم المالية: الغياب والتلف ⇒ الافتراضي **يُكتب**؛ الفراغ ⇒ لا زرع فوقه |
| الاستقلال | كتابة قائمة لا تمسّ قائمة أخرى (مفاتيح ديناميكية) |

## 5) فرق واحد مقصود ومُعلَن

حين لا توجد بيانات، كانت `getCommitments()` و`getVisits()` تُعيدان **مرجع** الثابت الافتراضي نفسه (وليس نسخة). اليوم تُعيد نسخة، فلا يمكن لمستدعٍ أن يعدّل `DEFAULT_DEBT_COMMITMENTS` بالخطأ عبر `push`. لا تغيير في المحتوى، وأمان أفضل.
